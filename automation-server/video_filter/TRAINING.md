# 手动训练与分标签验收

模型仅通过训练页面或手动训练 API 启动。首次样本就绪、新增样本、标签变化均不会自动创建训练任务；摘要提取、预测和分类继续按原流程调度。标签变化时旧模型提示需要更新，直到手动训练的新版本通过验收才替换。

## 验收指标

喜欢和不喜欢分别统计验证集的真实样本数、预测数量、预测正确数、预测错误数、精确率和召回率。

- 精确率 = 预测正确数 / 预测为该标签的数量。例如预测 100 个不喜欢视频，其中 90 个确实不喜欢，精确率为 90%。
- 召回率 = 预测正确数 / 真实属于该标签的样本数。例如实际有 100 个不喜欢视频，找出其中 70 个，召回率为 70%。
- 没有预测为该标签的样本时，精确率显示为空，该标签不能通过验收。

两类精确率必须同时达到各自门槛才启用新模型。默认门槛均为 80%，可在训练页面分别修改，设置随本次训练任务和模型结果保存。未达标的版本保留成绩，原活动模型继续使用。

分组 JSON 的 `training` 可配置默认门槛：

```json
{
  "activation_like_precision": 0.8,
  "activation_dislike_precision": 0.9
}
```

手动训练 API 也可传入 `acceptance: {"like_precision": 0.8, "dislike_precision": 0.9}`，取值为 0 到 1。页面输入采用百分数；单次设置不会修改分组配置文件。相同模型已有排队或运行任务时复用该任务；设置不同则提示等待。完成后可对相同数据再次手动训练。

## 验证范围

默认按标签比例划分 70% 训练集、30% 验证集。优先从现有分类阈值候选中选择同时达标的阈值，再以平衡准确率选择覆盖更好的候选；没有达标候选时保存未通过的成绩。平衡准确率和 ROC-AUC 仅供参考，不参与新验收，旧配置字段继续兼容读取。

分类阈值也在这份验证集上选择，因此验证成绩不等于独立测试集或未来用户反馈的表现。页面单独展示实际反馈成绩。旧模型未保存分标签验证数据时显示为空，需要新训练才能补齐；不会把旧指标冒充新验收成绩。
