# Video Compression 产品与技术规范（PSD）

## 1. 文档目的

本文档是 `video_compression` 的统一产品与技术基线，整合原始需求、前期调研和 AI 编程执行计划，用于指导实现、测试、验收与后续维护。

## 2. 产品目标

通过本地定时任务自动识别原视频，将不符合目标规格的视频压缩为 HEVC，在保证可播放和基本画质的前提下降低磁盘占用，并安全移动到成品目录。

优先级为：数据安全 > 成品有效性 > 规格一致性 > 压缩效率 > 编码速度。

## 3. 范围

### 3.1 包含

- 扫描指定目录中的 MP4 文件。
- 判断文件是否写入稳定，避免处理尚未复制完成的视频。
- 使用 FFprobe 获取编码、分辨率、旋转、帧率、时长和平均码率。
- 使用 NVIDIA NVENC 转码为 HEVC。
- 保留原始宽高比和音轨。
- 验证缓存成品与最终落盘副本。
- 验证成功后删除源视频，失败时保留源视频。
- 使用数据库记录任务状态、错误和成品路径。
- 任务异常中断后恢复处理、验证和待清理状态。

### 3.2 不包含

- 视频剪辑、拼接、加字幕、水印或内容审核。
- 浏览器上传、云端转码或公网服务。
- 自动安装 FFmpeg、驱动或 Python 依赖。
- 自动执行 Alembic 数据库升级。
- 当前版本不处理 MP4 以外的容器，也不复制字幕和附件流。

## 4. 成品规格

| 项目 | 规范 |
| --- | --- |
| 容器与文件名 | MP4；文件名与源文件完全一致 |
| 视频编码 | HEVC/H.265 |
| 码率控制 | VBR，平均视频码率不得超过 5,000,000 bps |
| 目标平均码率 | 4,500,000 bps，为上限留出浮动余量 |
| 帧率 | 保留不超过 30 FPS 的源帧率；超过 30 FPS 时降为 30 FPS |
| 横版尺寸 | 宽不超过 1920，高不超过 1080 |
| 竖版尺寸 | 宽不超过 1080，高不超过 1920 |
| 缩放 | 保持显示宽高比、不放大、输出宽高为偶数 |
| 音频 | 保留全部音轨并直接复制，不重复编码 |
| 播放优化 | MP4 使用 `faststart`，便于快速起播 |

方形视频按保守边界处理，最大输出为 `1080×1080`。

## 5. 处理判定

源视频满足以下全部条件时直接安全移动，否则执行转码：

1. 平均视频码率可读取且不超过 5,000,000 bps；
2. 编码为 HEVC/H.265；
3. 显示尺寸符合横版或竖版限制；
4. 帧率可读取且不超过 30 FPS。

该规则解决了原需求中“低码率直接移动”与“所有成品必须为 HEVC 且尺寸合规”的冲突，确保输出目录中的视频规格一致。

## 6. 系统流程

```text
每 30 秒扫描源目录
        ↓
记录文件大小和修改时间
        ↓
连续一次扫描未变化（至少稳定 30 秒）
        ↓
原子领取一个 READY 任务
        ↓
FFprobe 分析源视频
        ↓
全部合规？──是──→ 验证源文件
    │                    │
    否                   └────────┐
    ↓                             │
NVENC 转码到项目缓存              │
    ↓                             │
验证缓存成品                      │
    └──────────────┬──────────────┘
                   ↓
复制到输出目录隐藏临时文件
                   ↓
记录 VALIDATING
                   ↓
再次验证完整音视频
                   ↓
无覆盖地发布为原文件名
                   ↓
记录 CLEANUP_PENDING
                   ↓
删除源视频并标记 COMPLETED
```

任一检查或外部程序失败时，不删除源文件；保存经过长度限制的错误信息，并将任务标记为可诊断失败。

## 7. 技术方案

### 7.1 技术栈

- 服务框架：Flask、Flask-SQLAlchemy、Flask-APScheduler；
- 转码与探测：FFmpeg、FFprobe；
- Python 集成：标准库 `subprocess`，使用参数列表而不是 Shell 字符串；
- 默认编码设备：NVIDIA RTX 3060 Ti 的 `hevc_nvenc`；
- 数据库迁移：Alembic。

不引入 `ffmpeg-python`、PyAV 或 MoviePy；当前需求使用标准库即可完整控制退出码、超时、日志和命令参数。

### 7.2 模块职责

| 模块 | 职责 |
| --- | --- |
| `video_compression/probe.py` | FFprobe JSON 解析、旋转与平均码率识别、完整解码验证 |
| `video_compression/policy.py` | 转码判定、目标尺寸、规格校验 |
| `video_compression/transcoder.py` | 构造和执行 FFmpeg NVENC 命令 |
| `video_compression/service.py` | 缓存、双重验证、安全发布和源文件清理 |
| `video_compression/models/` | 持久化任务及状态 |
| `video_compression/schedules/` | 30 秒扫描、稳定性判断、原子领取和恢复处理 |

## 8. FFmpeg 编码基线

```text
-c:v hevc_nvenc
-preset p6
-tune hq
-rc vbr
-b:v 4500000
-maxrate 5000000
-bufsize 10000000
-cq 24
-rc-lookahead 32
-spatial-aq 1
-temporal-aq 1
-multipass fullres
-pix_fmt yuv420p
-c:a copy
-movflags +faststart
```

参数意图：

- `p6 + hq`：偏向离线高质量，而非最快速度；
- `VBR + CQ 24`：按场景复杂度动态分配码率；
- `4.5 Mbps` 目标与 `5 Mbps` 峰值：兼顾空间和最终平均码率上限；
- `lookahead + 空间/时间 AQ + fullres multipass`：改善复杂场景的码率分配；
- `yuv420p`：保持常见播放器兼容性；
- `-metadata:s:v:0 rotate=0`：物理旋转缩放后清除旧旋转标记。

缩放使用 Lanczos。只有源帧率高于 30 FPS 时才添加 `fps=30`，不会把 24、25 或 29.97 FPS 强制改为 30 FPS。

## 9. 配置规范

所有机器相关路径通过 `automation-server/env.py` 中的 `EnvConfig` 获取：

```env
VIDEO_COMPRESSION_SOURCE_DIR=<video_source_dir>
VIDEO_COMPRESSION_OUTPUT_DIR=<video_output_dir>
VIDEO_COMPRESSION_FFMPEG_BIN_DIR=<ffmpeg_bin_dir>
```

约束：

- 源目录与输出目录不得相同；
- 配置示例不得包含真实本机路径；
- 缓存目录为 `automation-server/video_compression/cache/`，必须被 Git 忽略；
- FFmpeg 目录内必须存在 `ffmpeg.exe` 和 `ffprobe.exe`。

## 10. 任务状态与恢复

| 状态 | 含义 |
| --- | --- |
| `waiting_stable` | 新发现或仍可能写入中的文件 |
| `ready` | 文件稳定，等待领取 |
| `processing` | 已原子领取，正在分析或转码 |
| `validating` | 任务暂存成品已生成，等待验证或无覆盖发布 |
| `cleanup_pending` | 成品已发布，等待删除源文件 |
| `completed` | 源文件已清理，任务完成 |
| `failed` | 处理失败，源文件保留，错误可诊断 |

调度器设置 `max_instances=1` 限制单进程内的重叠执行，并使用 PostgreSQL advisory lock 防止多个服务进程同时执行视频任务。新任务发现使用数据库唯一约束和冲突安全插入保证幂等；数据库领取时同时校验任务 ID 和状态，防止同一任务被重复启动。

任务使用由任务 ID 派生的确定性工作文件和发布暂存文件。新调度进程只有取得同一个 advisory lock 后才协调遗留状态：`processing` 可安全回到 `ready` 或进入 `validating`，`validating` 可通过暂存文件与最终文件的硬链接身份继续发布，`cleanup_pending` 重新验证成品后完成源文件清理。归属无法证明的同名输出进入 `failed`，同时保留源文件和既有输出。

## 11. 数据与迁移安全

任务表为 `video_compression_mission`，保存：源路径、文件名、大小、修改时间、稳定检查次数、状态、尝试次数、成品路径、错误信息和时间戳。

Alembic 迁移必须遵循：

- `upgrade()` 只能创建本项目表和自身索引；
- `downgrade()` 只能删除本项目索引和本项目表；
- 不删除、重建或修改其他业务表；
- 不清理或覆盖任何历史数据；
- 未获得明确授权时只生成和审查迁移，不执行 `alembic upgrade`。

## 12. 文件安全规则

1. 不直接向最终文件名写入转码数据；
2. 缓存成品必须先通过 FFprobe 规格检查和 FFmpeg 完整解码；
3. 输出目录中的隐藏临时副本必须再次完整验证；
4. 最终发布不得覆盖已存在的同名文件；
5. 只有最终成品发布成功后才能删除源文件；
6. 验证失败、超时、编码失败、复制失败或同名冲突时均保留源文件；
7. FFmpeg 日志使用 UTF-8 容错读取并限制错误长度，避免中文 Windows 的 GBK 解码异常和日志失控。

## 13. AI 编程执行计划

### 阶段一：基础结构

- 扩展 `EnvConfig` 和 `.env.example`；
- 新建独立 `video_compression` 子包；
- 忽略缓存和真实运行配置。

### 阶段二：媒体处理核心

- 实现 FFprobe 数据模型与解析；
- 实现尺寸、帧率、编码和码率策略；
- 构造 NVENC 命令，并为子进程设置退出码检查、超时和安全日志解码；
- 实现缓存、双重验证、无覆盖发布与成功后源文件删除。

### 阶段三：持久化与调度

- 新建任务模型和仅操作自身表的 Alembic 迁移；
- 实现文件稳定性检查、任务状态转换和原子领取；
- 注册 30 秒 scheduler，并限制重叠执行；
- 实现 `processing`、`validating` 和 `cleanup_pending` 的中断恢复。

### 阶段四：验证

- 运行 Python 编译检查；
- 单元测试覆盖尺寸策略、参数构造、日志编码、安全发布、同名冲突和失败保源；
- 检查 Alembic head 与迁移操作范围；
- 使用隔离硬链接运行真实 NVENC 样片，保留原始样片；
- 使用 FFprobe 核对编码、尺寸、帧率和平均视频码率；
- 完整解码视频与所有音轨，并确认测试源入口已删除。

## 14. 验收标准

- Scheduler 每 30 秒触发且不会处理仍在写入的文件；
- 不合规 MP4 能转为 HEVC，尺寸、帧率和平均视频码率满足第 4 节；
- 合规 MP4 不重复转码，只执行同等安全级别的验证和移动；
- 输出文件名与源文件完全一致；
- 音频存在时全部保留且可解码；
- 成品验证成功后源文件被删除；任何失败场景下源文件仍存在；
- 已存在同名输出不会被覆盖；
- 任务失败原因可从数据库诊断；
- 主进程异常退出后，遗留的 `processing`、`validating` 和 `cleanup_pending` 能安全收敛，不会永久卡住；
- 无法证明归属的同名输出不会被覆盖、采用或触发源文件删除；
- 新迁移不包含针对其他表的删除、修改或数据清理操作；
- 配置和缓存不会泄露本机路径、真实数据或大体积产物到 Git。

## 16. 后续可选优化

- 增加 `libx265` 高压缩率档位和 `hevc_qsv` 备用硬件档位；
- 根据低运动、高运动和暗场样片比较 4、4.5、6 Mbps 的质量与体积；
- 增加长时间无进度检测、取消机制和进度持久化；
- 明确业务需要后再扩展 MKV、字幕流或多视频流支持。
