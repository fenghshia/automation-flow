# 公开仓库与脱敏专项规则

本文件在配置、日志、样例数据、Git 操作或 GitHub 发布相关任务中强制加载。目标是让代码可公开管理，不负责为仅本地使用的 HTTP 接口增加访问控制。

## 识别范围

公开前检查源码、脚本、配置、迁移、浏览器代码、用户脚本、文档和待提交文件，至少覆盖：

- 数据库连接串、用户名、密码、API key、token、cookie、Authorization/header 值、私钥和会话密钥；
- 真实姓名、履历、邮箱、电话、账号标识及其他个人信息；
- 私有域名、固定内网 IP、本机绝对路径、NAS/下载目录等环境专属信息；
- 数据库文件、向量库、下载产物、日志、缓存、打包产物以及可能包含真实数据的 JSON/SQL 文件。

扫描结果只报告文件路径、行号和秘密类型，值应遮盖；不得为了说明问题而复制完整秘密。

## 修改规则

1. 运行时秘密使用环境变量或不纳入版本控制的本地配置读取。仓库只保留无真实值的 `.env.example` 或等价示例，并说明必填项。
2. 非秘密但因机器而异的地址、端口和路径也应配置化；默认值只能是安全、通用且不泄露本机信息的值。
3. `.gitignore` 应覆盖本地环境文件、密钥、数据库或向量库存储、日志、缓存、下载物和扩展构建产物；不要忽略源码或必要迁移。
4. 测试和文档使用明显虚构的数据，如 `example.invalid`、占位 token 和临时目录。
5. 日志不得输出密码、token、cookie、完整请求头或包含敏感参数的 URL；调试输出也遵守此规则。
6. 不用删除文件、改写 Git 历史或轮换凭据来“顺便修复”。这些操作需要用户明确授权。

## GitHub 发布检查

当用户要求初始化 Git、提交、推送或判断是否可公开时：

1. 先确认准确的待发布范围和 `.gitignore`；若尚未初始化 Git，扫描整个仓库候选文件。
2. 使用本地搜索检查高风险键名、连接串、私钥头、凭据型 URL 和环境专属数据；避免让扫描命令打印秘密值。
3. 逐项确认命中的内容已配置化、替换为虚构值或排除；二进制和数据库文件按类型审查，不能因文本搜索无结果就判定安全。
4. 仅在检查通过后执行用户明确要求的 Git 操作。提交前再次检查实际暂存文件。
5. 若秘密曾进入 Git 历史，停止推送并报告影响范围；轮换秘密与清理历史须由用户授权后分别执行。

## 停止条件

无法判断某个值能否公开时，将其按敏感信息处理并请求用户确认。不得声称仓库“已脱敏”或“可安全公开”，除非实际完成了上述范围的检查。
