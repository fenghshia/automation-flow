# 自动化子项目统一规则

适用于 `automation-server/<project_name>/**`。这是各业务流水线的公共规则；开始修改前同时遵循根目录 `AGENTS.md` 和 `.agents/automation-server.md`。仅在目标位于 `browser-plugin/` 或 `tampermonkey/` 时，再读取对应技术专项规则。

## 模块边界与注册

- 每个子项目保持独立，并在包内显式暴露需要注册的 API、模型和定时任务。新增或移动模块时，沿注册链检查该项目各级 `__init__.py`、`main.py`、`init_db.py` 和 `migrations/env.py`，确保需要的符号会加载且不会重复注册。
- `apis/` 仅接收本地客户端请求、调用业务逻辑并处理事务边界；`models/` 定义持久化状态；`schedules/` 领取并处理后台任务；被多个入口复用的业务逻辑放在子项目的普通模块中。
- 不从一个业务子项目直接导入另一个子项目的内部模块。确认至少有两个调用方后，才将真正通用的能力提取到职责明确的公共模块。
- 改动路由、请求或响应字段、任务状态、文件命名或持久化数据时，先沿“客户端或调用方 → 本地 API → 数据库任务 → 调度器或外部执行器”检查所有生产者和消费者。

## 任务、数据与外部调用

- 保持既有状态值及转换的语义兼容；新增状态或转换时，同步更新模型、API、调度逻辑，并覆盖失败和重试路径。
- 领取任务须防止调度器重叠导致重复处理。外部调用失败时，将任务置于可诊断、可重试的明确状态，不得长期停留在处理中。
- 下载目录、执行器地址、请求头和其他机器专属值必须通过配置提供；新代码不得固化真实路径或敏感值。文件名处理应考虑空值、重复、过长名称及 Windows 禁止字符，除非用户要求，不改变既有命名格式。
- 变更数据库模型时，评估 API、定时任务、现有数据和 Alembic 迁移；不得仅改模型就声称数据库已更新。生成迁移后人工检查 upgrade/downgrade 与数据损失风险；除非用户明确要求且目标明确，不执行迁移。

## 客户端兼容与验证

- 子项目含有浏览器扩展、用户脚本或其他本地客户端时，修改 API 契约须同步检查全部客户端的 URL、HTTP 方法、字段名和错误处理。
- 页面结构、第三方接口和本地服务都可能不可用；选择器、拦截规则和调用范围应明确，失败时安全退出，不无限重试或影响无关页面。
- 验证优先覆盖受影响的路由、事务、状态转换、任务幂等性和迁移；测试使用隔离的 app context、临时数据库和 mock 外部调用，不连接真实数据库或处理真实任务。
